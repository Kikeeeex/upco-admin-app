# Decisiones y dependencias

1. **Stack local:** Next.js 16, React 19, TypeScript, Tailwind 4, Supabase JS/SSR y PostgreSQL. Versiones resueltas desde npm el 28/10/2026 y fijadas en `package-lock.json`. Las páginas oficiales de Next.js, Supabase y Microsoft devolvieron HTTP 403 por la política de salida del entorno; el flujo OAuth debe revisarse contra ellas antes de conectarlo a Entra corporativo.
2. **Acceso cerrado:** sin configuración de Supabase/tenant, no hay sesión ni datos. No se implementa cuenta local de prueba ni se confía en correo, dominio o metadatos editables.
3. **Tenant e identidad:** el tenant esperado se configura en servidor. Antes de permitir un usuario real se debe verificar que `tenantid` y `oid` provienen de la identidad Azure firmada y se corresponden con el registro de pertenencia. La forma exacta en que Supabase expone estos claims requiere validación con un tenant autorizado; hasta entonces la autorización debe fallar cerrada.
4. **Recursos externos:** UPCO debe aprobar proveedor/región, clasificación de datos, retención, respaldo, dominio, proyecto Supabase de desarrollo, registro Entra, consentimiento OAuth, callback de Entra `https://<supabase-project>.supabase.co/auth/v1/callback`, redirección de la app `<origen>/auth/callback` y usuario administrador inicial. El proyecto Supabase y el tenant se enlazan mediante `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` y `ENTRA_TENANT_ID`. La política de red debe permitir el host exacto de `SUPABASE_URL` una vez conocido. No hay valores reales en este repositorio.
5. **Pruebas:** usar solo datos sintéticos. Las pruebas locales de lógica y SQL no sustituyen una prueba de OAuth con cuenta corporativa autorizada ni una revisión de seguridad previa a producción.
6. **Identidad:** `src/features/auth/authorize.ts` lee `tenantid` y `oid` desde `user.identities[].identity_data` del proveedor Azure y rechaza su ausencia. Se debe comprobar con una sesión real que Supabase suministra esos claims de forma estable y no editable antes de habilitar una membresía. El proxy renueva cookies; rutas y acciones vuelven a comprobar autorización.
